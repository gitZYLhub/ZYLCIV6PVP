# 项目文档约定

`docs` 保存开发资料，不进入 Civilization VI 运行包。玩家可见变化写入根目录 `CHANGELOG.md`，调查过程和验证证据写入 `WORKLOG.md`，长期设计与阶段门分别写入 `ARCHITECTURE.md`、`REFACTOR_PLAN.md` 和 `TEST_MATRIX.md`；1.4.x 玩法移入 2.0 的逐项边界见 `PORT_1.4_TO_2.0.md`。

## 每次改动的最低记录

1. 开工前在 `WORKLOG.md` 建立目标或在现有条目下追加范围。
2. 写明触及的模块、风险和“不在本次范围”的事项。
3. 完成后记录执行过的验证命令及结果；无法在本机执行的游戏内测试必须明确标为待测。
4. 玩家可见行为、默认值、兼容性、性能或网络语义变化同步写入 `CHANGELOG.md` 的“未发布”。
5. 规格变化同步更新 `ZYLPVPMOD1.3.0修改大全.md` 的 2.0 验收映射或后续 2.0 规格，禁止只改代码不改契约。

## 工作日志条目模板

```markdown
### YYYY-MM-DD / Mx-主题

- 目标：
- 范围：
- 设计决定：
- 修改：
- 验证：
- 风险/待办：
- 提交：
```

工作日志采用追加式记录。发现结论后来被推翻时保留原结论，并在新条目中引用和纠正，避免失去问题演变过程。
