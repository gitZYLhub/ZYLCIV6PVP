# 1.4.x → 2.0 迁移对账

本文记录把 1.4.x 开发线相对 1.3.0 的玩法变化移入 2.0 重构线的结果。

## 对比基准

- 1.3.0：提交 `1852e1d4ddc5abcfc4507885fc1141866a9154e0`（标签 `v1.3.0`）。
- 1.4.x：分支 `codex/1.4.0`，对账至提交 `d9cddf7`；最后一个玩法提交为 `68ae43e`（1.4.2）。
- 2.0：分支 `codex/refactor-2.0`。本次迁移保留 2.0.0 版本号和重构后的模块化清单，不复制 1.4.2 的版本元数据。

1.4.x 相对 1.3.0 共触及 30 个文件。版本号、握手字符串、旧式 `ZYLPVPMOD.modinfo`、旧校验器和说明文档不直接复制；其玩法语义分别映射到 2.0 的源文件、清单片段、数据库契约和模块化验证器。

## 2.0 重构适配

1.4.x 的单文件 ModInfo 登记被拆入以下 2.0 模块：

- `manifest/criteria/07-rich-mainland.xml`：共享、FFA、普通组队、横向组队和环形组队条件。
- `manifest/actions/frontend/07-rich-mainland.xml`：四张地图的配置和本地化动作。
- `manifest/actions/ingame/07-rich-mainland.xml`：四个入口脚本导入及四套条件化地图数据库动作。
- `manifest/files/07-rich-mainland.xml`：新增横向/环形共 8 个运行时文件。

地图配置 SQL 会在四个互斥的 `MAP_SCRIPT` 条件下写入相同的自定义地图尺寸主键。数据库重复键白名单据此登记为“互斥提供者”，并设置 `finalValueProbeRequired: false`；它们不能在同一运行时配置同时激活，因此不应要求单一 profile 的最终值探针同时覆盖四套值。

2.0 原有的三处 Lua 安全读取继续保留，而不是被 1.4.x 源文件覆盖：

- 城邦放置选项先保存 `MapConfiguration.GetValue` 返回值，再调用 `tonumber`。
- Rich Mainland 富饶度先保存配置值，再调用 `tonumber`。
- 开局加成的玩家号与奖励类型先保存配置值，再调用 `tonumber`。

这些处理覆盖 Civ VI API 在配置键不存在时可能返回零个 Lua 值的情形。

## 未移植项目

以下差异属于 1.4.x 发布包装，而不是应叠加到 2.0 的玩法：

- `Version=142`、`1.4.2` 显示名称和联机握手字符串。
- 1.4.x 的整体 `ZYLPVPMOD.modinfo` 和旧式组装脚本改动。
- 1.4.x 的旧单文件校验器；相同契约已加入 2.0 的模块化验证器。
- 1.4.x 专属总览文档及其中的提交占位/发布记录。

## 自动验证

`tools/validate.ps1` 现在覆盖：

- 俄罗斯城市拉夫拉需求集、Modifier 绑定、城市中心包含关系及旧相邻规则负向检查。
- 开局加成的存活主要玩家判断、观察者排除和 `IsHuman` 负向检查。
- 四张地图的文件、条件、动作、2～12 人尺寸、默认设置、入口标志、生成核心关键路径及本地化。
- 1.4.2 的 2 列接缝、横向/环形深海边界、岛屿/浅海、横向条带大陆和雨林聚簇关键路径。
- 数据库主键、Insert-Select、写集合、互斥地图尺寸提供者和最终值探针契约。

自动验证只能证明静态结构和契约一致；种子质量、实际出生位置、岛屿形态、OOS 和保存重载仍须按根目录 `TEST_CHECKLIST.md` 在 Civ VI 中实测。
