# ZYLPVPMOD 2.0 重构计划

## 总原则

- 冻结优先：`v1.3.0` 是回归基准，所有工作只在 `ZYLPVPMOD2.0`。
- 先表征后改动：没有静态断言或人工复现步骤的高风险模块，不做结构性改写。
- 小步提交：一次提交只跨越一个清晰责任边界，可单独回滚。
- 行为变化显式化：玩家可见差异必须进入更新日志和测试矩阵。
- 联机确定性优先：共享状态只能由确定的权威端写入，接收端幂等应用；游戏逻辑不依赖 UI 刷新频率、当地时间或无必要随机数。
- 发布与源码分离：Workshop 产物只含运行文件，文档、工具、缓存和测试证据留在仓库。

## M0：冻结与全面盘点（完成）

- GitHub `main` 与 `v1.3.0` 保存冻结提交。
- 建立平行独立工作目录和 `codex/refactor-2.0`。
- 完成 `ZYLPVPMOD1.3.0修改大全.md`。
- 阶段门：基线校验通过，原目录干净且不再修改。

## M1：工程治理与可复现构建

- 建立 CHANGELOG、WORKLOG、架构和测试矩阵。

- 将版本元数据收敛到单一来源，修复“组装脚本并不真正组装”的问题。
- 构建输出增加文件数、体积、哈希和平台组成报告。
- 阶段门：连续两次构建产物文件清单与哈希一致；运行包不含开发文件；基线行为断言仍通过。

## M2：ModInfo 与校验器模块化（进行中）

- 将校验器拆为清单、XML、数据库契约、Lua 静态、地图、UI、联机和发布包检查。
- 为每个模块设置所有者、条件、文件输入和期望不变量。
- 当前进度：已抽出可复用的 Lua 生命周期/正式日志、冻结动作图/分域源一致性、工程边界/XML、运行资产所有权、活跃运行文件安全、包身份/版本/多人握手、BBG 7.4.6 本地化闭合、BBG 图标/最终玩法文本/嵌入 tooltip/上游文明平衡、ZYL 最终 Gameplay 状态、数据库时代/秘密结社返还/最终参数修复、最终大厅配置/计时器/房主重置、BBM 根美术依赖与上游坏引用防回流契约、Team PVP Secret Societies、BBG Expanded 六资源、行业/公司、精选万神殿/地热矿山、开局加成/初始移民及海岸/内陆领袖变体完整纵向契约、发布 profile/平台资产配对、联机契约、Rich Mainland 地图契约、完整 UI 契约和身份模式纵向契约模块，各模块均有正反样例；联机模块覆盖大厅与五类控制器，地图模块完整覆盖 Rich Mainland，UI 行为断言已全部迁出主入口，身份模块覆盖大厅配置与只读展示闭包。已建立冻结 1.3.0 Action/Criteria/Files 规范图指纹和可重复报告；108 条 Criteria、32 条 FrontEnd Actions、251 条 InGame Actions 和 1077 条 Files 已全部迁移为分域源片段并由组装器确定性生成，48 个休眠文件也已移出代码成为显式清单。其余数据库契约、其他地图和集成边界校验仍待拆分。
- 阶段门：生成结果除预定元数据外与冻结动作图等价；故意删一个文件、重复一个动作或破坏一个条件时测试必须失败。

## M3：大厅与联机状态重构

- 从 `stagingroom.lua` 提取配置仓储、聊天命令、版本握手、投票、Ban/Pick、身份局、玩家槽位和刷新调度。
- 建立统一命令解析表：命令、别名、参数、权限、冷却、幂等键和反馈。
- 建立脏标记刷新：事件只标记领域，UI 帧按需要合并刷新；移除固定周期完整刷新和正式环境日志洪泛。
- 建立对称的事件注册/注销管理。
- 广播按状态版本去重，批量提交相关配置，避免同一用户操作触发多轮全量广播。
- 当前进度：大厅轮询已降为 1–5 秒阶段节流，配置写入按值去重，Context 全局监听已成对注销；原有 88 个活跃直接日志调用点中删除启动日志、其余 87 个改为 `.debug` 显式启用，且移除了调试日志/命令中三次重复 `GetNextID()` 广播副作用和一次昵称写入。随机分队和批量关闭空槽已从逐玩家广播收敛为每次操作一次 PlayerInfo；匿名昵称事件由全房间查找改为直接索引；跳过选人的随机领袖列表修复越界并改为线性洗牌；周期刷新对赛事关键配置的读取由 13 次降为 4 次；握手轮询只在玩家状态转换时重绘对应条目；4 个全仓库零引用的旧握手/标签页函数已删除。领域拆分、其余脏域刷新和完整广播版本化仍待完成。
- 阶段门：房主/客户端/观察者、掉线重连、热载入、重开和投票流程通过双客户端测试；广播次数和刷新耗时有基准对比。

## M4：游戏脚本确定性与生命周期

- 移除无必要的同步随机数调用和每回合调试打印。
- 审核所有 gameplay context 事件的重复注册、读档幂等和主机权限。
- 开局奖励、时代长度、强制结束回合、地图标记和秘密结社脚本建立状态机及持久化契约。
- 阶段门：新局、存档加载、热座、普通多人和断线重连不产生重复单位、重复效果或随机流偏移。

## M5：数据库精简与兼容层

- 对 247 个 SQL、XML 数据源建立写集合和最终值报告，识别真正重复、死写和被最终覆盖的中间层。
- 仅在证明最终数据库等价后合并重复 SQL；DLC/模式条件保持隔离。
- 统一重复 Requirement/Modifier 定义，清理孤儿参数和无引用对象。
- 把 ZYL 最终规则集中为可检索模块，避免依赖隐式加载顺序。
- 阶段门：关键表快照或日志数据库查询与冻结基线对比；每个有意差异写入 CHANGELOG。

## M6：UI 组合与局部设置

- 为每个 Firaxis UI Context 确定唯一最终替换者，其他组件通过扩展钩子组合。
- 合并 UnitFlagManager、DiplomacyDealView、DiplomacyRibbon、MapPin 和 TopPanel 的重复责任。
- 缓存昂贵查询，按数据变更失效；避免在 Update/Tick 中扫描全玩家、全城市或全单位。
- 阶段门：不同分辨率、语言、DLC、观察者和禁功能配置下无重复控件、空引用或输入冲突。

## M7：地图性能与确定性

- 给 BBM/Rich Mainland 日志加等级和一次性摘要。
- 对出生重试、资源兜底、山地填充、城邦放置建立计时和计数器。

- 输出包体积预算和重复资产报告。
- 当前进度：universal 构建已按 Files 清单隔离源码/休眠文件，并把 601 个已知 UTF-8 运行文本在临时产物中规范为 LF；LF/CRLF 工作区变体已证明生成相同聚合哈希，二进制抽样逐字节一致。169 组 Windows/macOS 资产已通过路径配对和 Action 非直引检查，56 个资产定义文件也不含平台目录硬编码；Windows 与 macOS 包均从当前 1072 个文件、776,223,699 字节裁剪为 903 个文件、约 442.48 MB，并在 PowerShell 5.1/7 得到相同聚合哈希。三种 profile 已设置硬性体积预算并在报告中登记重复二进制内容；单平台包尚余 14 组、1,845,008 字节理论重复量，但必须按路径契约逐组审查，不能自动删除。目标平台实机加载仍待完成。
