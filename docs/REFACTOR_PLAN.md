# ZYLPVPMOD 2.0 重构计划

## 总原则

- 冻结优先：`v1.3.0` 是回归基准，所有工作只在 `ZYLPVPMOD2.0`。
- 先表征后改动：没有静态断言或人工复现步骤的高风险模块，不做结构性改写。
- 小步提交：一次提交只跨越一个清晰责任边界，可单独回滚。
- 行为变化显式化：玩家可见差异必须进入更新日志和测试矩阵。
- 联机确定性优先：共享状态只能由确定的权威端写入，接收端幂等应用；游戏逻辑不依赖 UI 刷新频率、当地时间或无必要随机数。
- 发布与源码分离：Workshop 产物只含运行文件，文档、工具、缓存和测试证据留在仓库。

## M0：冻结与全面盘点（完成）

- GitHub `main` 与 `v1.3.0` 保存冻结提交。
- 建立平行独立工作目录和 `codex/refactor-2.0`。
- 完成 `ZYLPVPMOD1.3.0修改大全.md`。
- 阶段门：基线校验通过，原目录干净且不再修改。

## M1：工程治理与可复现构建

- 建立 CHANGELOG、WORKLOG、架构和测试矩阵。
- 建立行尾、忽略文件、源码/运行包边界。
- 将版本元数据收敛到单一来源，修复“组装脚本并不真正组装”的问题。
- 构建输出增加文件数、体积、哈希和平台组成报告。
- 阶段门：连续两次构建产物文件清单与哈希一致；运行包不含开发文件；基线行为断言仍通过。

## M2：ModInfo 与校验器模块化

- 按功能域定义动作清单和 Criteria，生成确定性 ModInfo。
- 生成结果与冻结 ModInfo 做语义差异，而不是依赖 4000 行手工 XML。
- 将校验器拆为清单、XML、数据库契约、Lua 静态、地图、UI、联机和发布包检查。
- 为每个模块设置所有者、条件、文件输入和期望不变量。
- 阶段门：生成结果除预定元数据外与冻结动作图等价；故意删一个文件、重复一个动作或破坏一个条件时测试必须失败。

## M3：大厅与联机状态重构

- 从 `stagingroom.lua` 提取配置仓储、聊天命令、版本握手、投票、Ban/Pick、身份局、玩家槽位和刷新调度。
- 建立统一命令解析表：命令、别名、参数、权限、冷却、幂等键和反馈。
- 建立脏标记刷新：事件只标记领域，UI 帧按需要合并刷新；移除固定周期完整刷新和正式环境日志洪泛。
- 建立对称的事件注册/注销管理。
- 广播按状态版本去重，批量提交相关配置，避免同一用户操作触发多轮全量广播。
- 阶段门：房主/客户端/观察者、掉线重连、热载入、重开和投票流程通过双客户端测试；广播次数和刷新耗时有基准对比。

## M4：游戏脚本确定性与生命周期

- 移除无必要的同步随机数调用和每回合调试打印。
- 审核所有 gameplay context 事件的重复注册、读档幂等和主机权限。
- 开局奖励、时代长度、强制结束回合、地图标记和秘密结社脚本建立状态机及持久化契约。
- 阶段门：新局、存档加载、热座、普通多人和断线重连不产生重复单位、重复效果或随机流偏移。

## M5：数据库精简与兼容层

- 对 247 个 SQL、XML 数据源建立写集合和最终值报告，识别真正重复、死写和被最终覆盖的中间层。
- 仅在证明最终数据库等价后合并重复 SQL；DLC/模式条件保持隔离。
- 统一重复 Requirement/Modifier 定义，清理孤儿参数和无引用对象。
- 把 ZYL 最终规则集中为可检索模块，避免依赖隐式加载顺序。
- 阶段门：关键表快照或日志数据库查询与冻结基线对比；每个有意差异写入 CHANGELOG。

## M6：UI 组合与局部设置

- 为每个 Firaxis UI Context 确定唯一最终替换者，其他组件通过扩展钩子组合。
- 合并 UnitFlagManager、DiplomacyDealView、DiplomacyRibbon、MapPin 和 TopPanel 的重复责任。
- 缓存昂贵查询，按数据变更失效；避免在 Update/Tick 中扫描全玩家、全城市或全单位。
- 阶段门：不同分辨率、语言、DLC、观察者和禁功能配置下无重复控件、空引用或输入冲突。

## M7：地图性能与确定性

- 给 BBM/Rich Mainland 日志加等级和一次性摘要。
- 对出生重试、资源兜底、山地填充、城邦放置建立计时和计数器。
- 缓存不变的地块分类，减少重复全图遍历，同时保持遍历顺序和随机调用顺序不变。
- 阶段门：固定种子地图哈希/摘要一致；各尺寸生成时间和峰值日志量优于基线；出生规则全部通过。

## M8：平台化发布与体积优化

- 生成 universal、Windows、macOS 三种发布清单；只有在确认 Civ VI 加载器路径要求后才移除非目标平台资产。
- 对重复二进制按内容哈希登记，禁止粗暴删除 `.dep` 或相对路径要求的文件。
- 输出包体积预算和重复资产报告。
- 阶段门：目标平台实机加载通过；universal 保持完整兼容；平台包的文件路径与 ArtDef 引用闭合。

## M9：2.0.0 收口

- 执行完整静态、构建、单机、地图和双客户端联机测试矩阵。
- 更新名称、ModInfo 数值、本地化标题、握手版本、README、CHANGELOG 和构建报告为 2.0.0。
- 生成迁移说明，特别标注存档兼容和需双方同步更新的要求。
- 创建 `v2.0.0` 候选提交；用户验收后再合并/发布。
- 阶段门：没有未解释的 1.3.0 行为缺失，没有未关闭的 P0/P1 联机问题，发布包可从干净克隆复现。
